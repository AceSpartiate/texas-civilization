# Triage of the 2026-09-28 audits — 2026-09-29

**Asked by the owner (2026-09-29):** *"triage the audit findings into a ranked list."*

**What this covers.** Every **serious** and **minor** finding in the four audits of 2026-09-28:
[design](2026-09-28-design.md) (S1–S36, M1–M35), [classroom](2026-09-28-classroom.md) (S1–S9, M1–M10),
[interactions](2026-09-28-interactions.md) (S1–S6, M1–M5) and [playthrough](2026-09-28-playthrough.md) (#2–#10). That is
**110 findings**. The blockers were all fixed before this, so they are not listed. Ids below are written as the audit's
initial and the finding: **D** design, **C** classroom, **I** interactions, **P** playthrough (so `D-S23` is design S23 and
`P-6` is playthrough #6).

**How it was checked.** Each finding was read against the code at `0ffa9663` (v2026.09.29.1). The audits were written at
`aa35088`. Where it was cheap, a finding was spot-checked:

- the audit's own fixtures were run again: `spring()` and `sceneFor` for I-S2, I-S5 and I-M2, `settled` for D-S11;
- in-process server scripts were run for C-S1, C-M1, C-M2, C-M3 and C-M4, and a `node -e` for D-M8;
- `tests/absence.test.mjs` and `tests/acting.test.mjs` were run.

Nothing in the game was changed. Everything ran on one computer, so there is no Chromebook, LAN or classroom claim here.

**How it is ranked.** The classroom is the test: real students on Chromebooks. Each item is weighed by three things:

- how often a real class of up to 30 meets it, over the 6 to 11 class days a game now takes at Study;
- how badly it hurts: wrong history, a stuck student, lost work, a teacher who cannot run the class, confusion, or unfairness;
- the effort: **S** is a day or less, **M** is a few days, **L** is a week or more.

Duplicates across the audits are merged into one item that lists every source id.
