# Technical foundation

Maturity: **PROTOTYPE**. The repository implements a bounded Gonzales foundation, not the full game or a classroom-ready deployment. [VISION.md](VISION.md) governs architecture; [HANDOFF.md](HANDOFF.md) and [docs/GATES.md](docs/GATES.md) record executed acceptance evidence. This document describes code behavior, not an independent claim that a gate passed.

## Runtime and source map

The application uses Node 22+ built-ins and browser HTML/CSS/canvas. It has no runtime package dependencies, build step, hosted database, or online AI requirement. It does now ship sprite art, served from this repository over the same server; nothing is fetched from anywhere else at runtime. Browser automation is separate development tooling. `npm start` runs [server/main.mjs](server/main.mjs); `npm test` runs the Node test files.

`server/main.mjs` explicitly selects `createGonzalesWorld`, 15 household slots, port 1835, seed `gonzales-1835`, and a 1000 ms timer interval. Development environment variables are `PLAYERS`, `PORT`, `SAVE_PATH`, `SEED`, `TICK_MS` and `TEXAS_DATA_DIR`. A saved world is loaded in preference to creating a new one; changing the seed does not reset an existing class.

A chore is a list of steps — `walk`, `travel`, `work`, `consume`, `produce`, `field`, `wear`, `mend` — and `advanceChores()` runs one step per person per tick after travel resolves. There is **no randomness anywhere in that path**: `FIC-GONZ-008` requires outcomes to resolve inside a visible risk, so tool wear is a fixed cost per use with the remaining uses shown before the work is chosen, and yields are fixed numbers stated on the control that spends them. `tests/chores.test.mjs` asserts the absence of `Math.random` in that file directly.

Which chores a person may be given, and the reason for any that are refused, are computed on the server and delivered in the projection as `work`. The client renders that answer; it never decides for itself what is possible. That is the fog-of-war rule applied to a control rather than to a fact.

**A cotton field used to come in as food.** `harvest-field` added to `resources.food` whatever the crop was, so half the class ate its cotton — not a balance choice, the game not knowing what it had grown. It now yields `cotton`, which nothing eats, and `sell-cotton` carries it to Gonzales at a fixed rate through the carrying rule every other hauling chore already uses. `HIST-GONZ-022`, `FIC-GONZ-019`.

**The arrival clock** (2026-09-12, `docs/SETTLING_IN.md` step 1). `TIMELINE` in `sim/directors.mjs` counts from dawn on September 28 (`ARRIVAL_MINUTES` = 1080 after the historical minutes from midnight on the 29th). Director code never reads `TIMELINE` directly for a comparison: `momentOf(world, key)` gives a moment on this class's clock, and subtracts the arrival for a class saved without `director.arrival`. `historicalDate` starts from dawn on the 28th when the marker is set.

**The two clocks** (2026-09-15, `docs/COLONIES.md` §5.7 and §6g). `sim/clock.mjs`: `TICK_MINUTES` = 20, the effort a tick always holds; `CALENDAR_SCALE` by `director.phase` (`home` 20, `news` 60, `gathering` 240, `campaign` 720 — the last two unused until build steps 5 and 6); `calendarMinutes(world)`, which answers 20 unless the class is on the real land (`map.source`) and answers 20 again while `deciding(world)` — the night of the crossing, where history fixes both ends of an open question. Nothing is stored, so no save version moved. `stepWorld` advances `world.minute` by it and passes it to `advanceRoutine`, which is entirely calendar work (food, spoilage, a wound mending, rest). `progressTravel` multiplies its ticks by `roadTicks` (sim/travel.mjs, 2026-09-18): `calendarMinutes / TICK_MINUTES` in a tick of an hour or less and for a rider carrying word (`ridesAllHours`: a courier, a relayed report, an express), so miles an hour of 1835 is constant there and `HIST-TEX-006`'s dates hold, and in a longer tick a day on the road - `ROAD_HOURS_A_DAY` = 7 hours of going in 24, spread evenly - so nobody else travels all day and all night (`FIC-GONZ-059`); `milesATick(world, entity)` is what the next tick carries, projected on a family's own travel as `step` for the page's out-of-sight rule; a courier's first tick in a stretched phase never carries him past halfway, so a short leg still has a tick of road to be seen on. `sim/encounters.mjs` gains `stretch`, `attention(world, minutes)` and `seenComing(world)`: `PATIENCE_MINUTES`, `PASSING_MINUTES`, `SPEAKING_MINUTES` and `SIGHT_MILES` are counts of ticks wearing fictional clothes, and stretch with the calendar rather than shrinking to a third of themselves. `resolveTimeJump` steps one tick's worth of calendar at a time.

**Kin is the world's, names are the student's, and ids are neither.** [sim/family.mjs](sim/family.mjs) holds both halves and keeps them apart. An entity's id never changes — `hh-1-thomas` stays `hh-1-thomas` however often somebody is renamed — which is what `CLAUDE.md` means by stable person IDs, and it matters because `skillsFor` and `visualVariant` are both derived from the id. A rename must not change what somebody is good at or what their face looks like, and it does not. The cost is that an id keeps its founding name, so a student's Bartolo may be `hh-3-thomas` underneath; that is ids not lying about identity, and it is the right trade.

Default names are **dealt** across a class rather than hashed per household. The obvious version — hash the id into a pool and take the remainder — was measurably bad: fifteen households produced seven distinct mothers and a run of four consecutive fathers called Feliciano. A remainder of a hash is not a shuffle. The pools are shuffled once from the world's seed and dealt in order, so fifteen households get fifteen different fathers, and thirty get each name twice, which is what places are like.

Who a family is is **fetched**, not sent. `/api/family` answers for the household on the cookie and nothing else; it is about four hundred and fifty bytes and changes only when somebody renames somebody. That is the same lesson as `/api/map` and `/api/chores`, learned here for the third time. See [docs/evidence/family.json](docs/evidence/family.json).

**Work can stop and ask.** A chore step `{ ask: 'shot' }` suspends the chore, writes the question and its options onto `entity.chore.ask` — texts and all, computed on the server from the person standing there — and advances nothing until `answer-chore` arrives or the person's own patience runs out (`ASK_PATIENCE`, two fictional hours, the same shape as a rider's). Later steps carry `when: ['take', 'wait']` and run only for the answers they belong to; `settleAsk` records whether the family chose or nobody was listening, because those are two different stories about the same household and the epilogue is built out of them.

The outcome contains no die. `steadyHand` is the whole rule — not tired, and hunting skill of two or more — and both halves are already visible to the student before they answer. It is also where the systems meet: fatigue comes from the road, the road's cost comes from the travel mode, so **how a family travelled decides whether it can shoot straight**. Nothing in that chain is new; it is four things that already existed finally touching.

It is deliberately general. The interpreter knows nothing about hunting: any chore can ask, and the ford, a trade or a crossing are the obvious next ones.

**A journey has a mode, and the mode owns the trade-off.** [sim/travel.mjs](sim/travel.mjs) is a table of three and imports nothing, because both [sim/world.mjs](sim/world.mjs) (which owns journeys) and [sim/chores.mjs](sim/chores.mjs) (which owns work) have to agree about what a mode is, and `chores.mjs` is handed `beginTravel` as a parameter precisely to keep an import arrow between them from existing.

Property that comes along gets its own travel record on the same route at the same speed, and `borrowedBy` names who took it. Both of those had been in the world since it was first built and neither had ever been used: `borrowedBy` was always null, and the art library has carried `ox-walk`, `horse-walk` and `wagon-loaded-travel` since the atlases landed, so a family's animals had never once been seen to leave the yard. What makes the ox rivalrous is not a lock but a fact - it is somewhere, and if it is not where you are, you cannot take it.

Two guards are worth knowing about. `handleMarch` and `handleChoice` write a decision down and *then* send somebody walking, so both ask `travelRefusal` before anything moves - a journey refused halfway through would leave a household that had agreed to go with nobody on the road. `beginChore` does the same for the same reason, keyed on whether the chore travels at all rather than on whether it hauls: a chore keeps its mode for the journey **home**, and that leg runs inside `advanceChores`, which is inside `stepWorld`. An impossible journey discovered there does not refuse one student's order; it stops the class.

No save version moved. A class saved before any of this has no `mode` on its travel records and no horse in its yards, and both absences read correctly: everybody walked, and that family has no horse. See [docs/evidence/travel-modes.json](docs/evidence/travel-modes.json).

**How fast a class is watched is not how fast the world is.** `PACES` in [server/app.mjs](server/app.mjs) names three tick intervals and the Host may change them mid-class; nothing under `sim/` can see the pace, so a tick is twenty fictional minutes and a settler walks three miles an hour at every one of them. The pace lives outside the world and outside the save, because it describes a room rather than a simulation. `tickMs` rides in the snapshot so the renderer can spread one tick's movement across one tick of real time — without that the client assumes a second, and a slower class walks for a second and then stands still.

This is what the owner's "moving way too fast" actually was. The speeds were right; one real second a tick was not. At 1200× real time a walking figure crossed 8.7 of its own drawn body lengths a second against 0.78 for a real walker, with a correct 2.8-step gait animation playing underneath — life-speed legs and a nineteen-hundred-foot stride. Zoom could never have fixed it: screen speed is scale times miles per second and the drawn height of a person is also proportional to scale, so the scale cancels. See [docs/evidence/pace.json](docs/evidence/pace.json).

**The lobby accepts orders and runs no clock.** `LOBBY_ACTIONS` in [sim/world.mjs](sim/world.mjs) names what a household may do before the class begins — its own work, its own people, its own travel — and `applyAction` refuses everything else with a reason. Anything addressed to another household waits, because that household may not have joined. Two independent guards keep the clock still, the server's tick timer and `stepWorld` itself, so a single mistake in either does not start time early; a test has to break both to observe the difference, and one does.

**Five joined households is a guard, not a wall.** Starting below five is refused once, with a count and an instruction, and a second deliberate press goes ahead. The world always holds `playerCount` households and the ones nobody joined simply take no orders, so the minimum is a pedagogical check rather than a technical requirement — and the way through is what makes a single-machine trial possible without a developer setting no teacher would find.

**Observation is a server rule, not a rendering one.** `observedBy()` returns the people a household may see: anyone standing at a site where one of that household's own people is standing, reduced to who they are, where they are, what they appear to be doing and their visible condition. Skills, chores, travel plans, commitments and a courier's `report` never travel. They arrive as `others`, deliberately a separate list from `entities`, so a person who is not yours cannot be commanded by accident. `tests/town.test.mjs` covers each of those, and the leak assertions were checked by injecting a careless spread and watching them fail.

**Two things are fetched once per class rather than per tick**: the map (`GET /api/map`) and the catalogue of work (`GET /api/chores`). Both are static for the life of a class. This is a pattern worth naming, because it has now been got wrong twice: shaded relief was three quarters of a student's payload before it moved, and the chore table was 4.46 KB of a 6.8 KB payload — six fixed sentences retransmitted to every student every tick. Availability stays on the tick, because it is a permission; the words describing the work do not.

Static art is served by a separate `/assets/` route rather than the fixed file map. It accepts only `png`, `webp` and `json` under `public/assets/`, rejects dot segments, encoded separators, Windows paths, null bytes and hidden files, resolves symbolic links before checking containment, and caps file size. It sends an ETag with `must-revalidate`; a sheet asked for with `?v=` and the first sixteen characters of its own SHA-256 (what `public/art.js` asks for, from the manifest's `sha256`) is sent `max-age=31536000, immutable`, so a device downloads the sheets once and does not ask again until a sheet changes. Scripts, styles and JSON of 1 KB or more go gzipped to a browser that accepts it, and the page's own files are `no-cache` with an ETag rather than `no-store` (`server/delivery.mjs`, docs/PERFORMANCE_LOAD.md). `tests/asset-http.test.mjs` exercises the traversal and escape cases; `tests/delivery.test.mjs` the compression and caching.

The Content-Security-Policy is `default-src 'self'` with `style-src 'self'` and `script-src 'self'`. **Inline `<style>` blocks and inline `<script>` are therefore blocked**, which is why every page here links a stylesheet instead of carrying one. Setting `element.style.left` from script is unaffected and is how the selection card is positioned.

`resolveDataDir()` picks the class data folder once, in this order: `TEXAS_DATA_DIR`; `<application folder>/data` whenever it is writable; otherwise `%LOCALAPPDATA%\TexasRevolution\data`. A read-only install directory therefore cannot prevent a class from starting. `resolveSavePath()` puts `classroom.json` in that folder unless `SAVE_PATH` overrides the save file alone. `scripts/appinfo.mjs` prints the resolved answer as JSON so the PowerShell launcher, stop helper and preflight read one source of truth instead of re-deriving the rule. `joinCandidates()` ranks physical adapters ahead of VPN and virtual ones; enumeration identifies candidates and never establishes that another device can reach them.

The lower-level `createClassroom()` factory defaults to `createWorld` and a 200 ms interval. This intentionally creates a scenario-free core for focused tests. Do not mistake that fixture default for the launched game's configuration. Omitting `savePath` creates an ephemeral in-process instance.

## Authority, protocol and identity

One Node process owns one World State. Browsers submit intentions and render returned projections; they never advance authoritative time or publish replacement world state. Simulation functions mutate a supplied plain-data world deterministically. Cryptographic session credentials are separate from the reproducible simulation seed. Seeded randomness currently initializes food; before adding random live outcomes, persist/version the generator state or use stable event-keyed draws so reload cannot change the result.

| Route | Contract |
| --- | --- |
| `GET /`, `/host`, `/app.js`, `/style.css` | Locally served application assets |
| `GET /health` | Listener/application/PID/launcher-nonce identification, plus whether this process is stopping and whether it supports a graceful stop; not a simulation or save-health test |
| `POST /api/host` | Validate private Host key and set Host cookie |
| `POST /api/join` | Validate class code and lobby capacity, issue student identity; existing authenticated students recover their assignment |
| `GET /api/state` | Current authenticated projection |
| `GET /api/events` | Full authenticated snapshots over SSE |
| `POST /api/command` | Validate authenticated role, command ID, action availability and entity ownership |
| `POST /api/rejoin` | Move an existing household to the device holding its family key. No class code, allowed after Start, never creates a household |
| `GET /api/families` | Host only. The roll of joined households by the name each student chose. Carries no keys, so it is safe to leave on screen |
| `GET /api/family-key` | Host only. **One** household's family key, asked for by name, for a student who has lost both their browser and their key |
| `GET /api/map` | Public geography, fetched once per class |
| `GET /api/chores` | The catalogue of work, fetched once per class |
| `POST /api/solo` | **Solo servers only** (`createClassroom({ solo: true })`). With the Host key: a new world, one player joined as `hh-1`, rolled, `running`; every stream closed; returns a one-use `playUrl`. Solo Mode, [DEPLOYMENT](docs/DEPLOYMENT.md#solo-mode-playtesting) |
| `GET /solo/enter?ticket=` | **Solo servers only.** Spends the ticket (two minutes, one use): sets that player's cookie and redirects to `/` |

A solo classroom also forces `listen` to `127.0.0.1` and refuses any request from a non-loopback address; `/health` reports `solo`. `server/main.mjs --solo` takes its folder, save and port from `soloPaths()` (`<data>/solo`, 1836 or `SOLO_PORT`), never from `SAVE_PATH` or `PORT`, and discards an unlocked solo save at start.

Host actions are `start`, `pause`, `resume`, `end`, `new-class` and `stop-server`; every other action reaches `applyAction` as a student intention and is rejected there. `stop-server` exists only when the process supplied an `onStopRequested` callback — `server/main.mjs` does, in-process test fixtures do not, and the Host projection carries a `canStop` flag so the control is never offered by a build that cannot honour it. It checkpoints a running class as **paused** before responding, because a saved running class resumes advancing on restart; then a transient `lifecycle` overlay is broadcast so connected browsers learn the teacher stopped the server before their streams end, and the process closes after a short flush delay.

`new-class` is refused unless the class is `lobby` or `ended`, so a live class cannot be discarded. It archives the last completed checkpoint through `archiveSave()`, then rotates `sessionId` and `sessionCode`, clears client assignments and command ledgers, and rebuilds the world from a fresh seed while keeping the configured class size. Because cookie names embed the session ID, rotation invalidates every previous student credential by construction; the response also re-issues the Host cookie under the new name and expires the old one, and student streams are closed so a previous student cannot silently inherit a household in the new class. Cookie names are therefore read per request rather than captured once.

Student bearer credentials are random tokens stored in `HttpOnly; SameSite=Strict` cookies with a seven-day maximum age. The save stores their SHA-256 hashes mapped to household assignments and display names. Identical display names are allowed; a name is never a recovery credential. The Host uses a distinct random key, kept in the private save and initial Host URL fragment. The browser exchanges that fragment for its HttpOnly cookie and removes the fragment from the displayed address. Neither key nor the student credential registry belongs in snapshots.

**Trading between households lives in [sim/trade.mjs](sim/trade.mjs) and is deliberately physical.** An offer exists only between two people standing at the same site; `together()` is the single predicate that decides it, and `advanceOffers()` runs each tick after travel and chores and deletes any offer whose two people have parted. There is no market, no order book and no way to deal with a household across the county, because a global market is the optimisation spreadsheet `CLAUDE_DEVELOPMENT_ROADMAP.md` §1D forbids. `world.offers` is keyed by id; the actions are `offer`, `accept-offer`, `decline-offer` and `withdraw-offer`, and all four are open to **any** family member rather than the principal, which is the whole point of the feature.

The ownership guard is the one `applyAction` already had. Every trade action names one of *our* people — the person making the offer, or the person it was made to — so "choose one of your family" is also what stops one household answering for another; on top of that, `respondToOffer` checks the offer's own household and the named entity. Goods are `food` and `seed` only, in whole amounts of one to twenty, and an offer must swap one good for a different one. Nothing is escrowed: affordability is re-checked at acceptance, and an offer whose goods were spent in the meantime fails with a plain sentence and closes. That is marked in the source with a `ceiling:` comment naming reservation as the upgrade path.

**No save version moved.** A class saved before trading existed simply had no offers, which is a correct empty answer rather than a missing field, so `world.offers` defaults on load and `validateWorld` accepts its absence. The alternative — bumping `saveVersion` to 4 — would have refused to open every existing class in exchange for nothing.

**What crosses the wire is one side of a bargain.** `offersFor()` writes every offer from the reading household's own point of view (`weGive` / `weGet`), carries the other person's name, their family's fictional name and their entity id, and carries nothing about their household's stores. The other person is necessarily already visible in `others`, because an offer cannot outlive standing together. `observedBy()` now also reports an observed person's family name, since every household is a copy of the same four names and `Thomas` alone cannot distinguish two of them; that name is the world's own fiction and is never the display name a student typed to join, which lives beside their credential on the server and is not part of the world at all.

**A family key is how a household gets back in.** Every household has one, eight symbols of a Crockford base32 alphabet — no I, L, O or U, so it can be read off one screen and typed on another without the 0/O and 1/I confusions. It is **derived, never stored**: `HMAC-SHA256(hostKey, sessionId + ':' + householdId)`, five bits per symbol, so no new saved state exists to migrate, no key survives `new-class` (which rotates `sessionId`), and forty bits make it unguessable at classroom scale. `POST /api/rejoin` takes only that key: it needs no class code, it works **after Start**, and it never creates a household — it moves an existing one to the device holding the key, minting a fresh credential and deleting the old one so a household keeps exactly one command ledger. Three rules bound it. A household whose stream is open **now** is refused with 409, because a key read off a neighbour's screen must not evict them. Wrong keys are throttled per address, five tries then a thirty-second cooldown. And a household is told its own key and no other — **the ordinary Host projection carries none of them**, because a teacher's screen is sometimes a projector. A student who has lost both their browser and their key is recovered through `GET /api/family-key`, which returns exactly one household's key on request; the Host control that uses it is closed by default, shows one family, and clears itself after thirty seconds. Revealing a key is not recorded anywhere, which is marked in the source with a `ceiling:` comment. `tests/rejoin.test.mjs` covers each, and the live browser proof is [docs/evidence/family-key-recovery.json](docs/evidence/family-key-recovery.json).

**Presence separates *away* from *gone*.** A mobile browser drops its SSE stream within seconds of the screen locking, so a count of open streams told a teacher that a student had left when they had not. The Host projection now carries `presence: { here, away, joined }`: `here` is streaming right now, `away` is a household whose stream closed within a ninety-second grace window. It is held in memory beside `runtimeFault` and `lifecycle` and is **deliberately never saved** — it describes this moment, not the class. Students are told nothing of it. The older `connected` field is unchanged and still means streams open now.

New joins require the lobby, correct code and an available slot. The supported configuration range is 5–30; Start requires five assigned households. Live connected count is separately computed from unique households with SSE streams. Reconnection with an existing credential works after Start and does not allocate another family. Each credential has its own authority: body fields cannot grant a different role or household.

Every accepted command has an ID retained in a per-student or Host ledger of **256 IDs**. Repeating a retained ID returns `duplicate: true` without another commit. This is bounded replay protection, not an indefinite exactly-once guarantee. The ledger is persisted. The UI has no durable offline action queue; failed actions surface an error.

SSE sends full projected snapshots tagged with the committed `revision`. Native `EventSource` reconnects; the server sends current state rather than replaying a `Last-Event-ID` history. Do not treat revisions as an event archive. Connection-count broadcasts may repeat a revision, and the emergency fault overlay can change a snapshot without a new committed revision. A page is not sent a snapshot whose content, revision aside, is what it was last sent - unless it made the change - so revisions a page receives can skip; pages seeing the same thing share one projection per broadcast; students' orders and connection changes are broadcast at most every 200 ms, while ticks, Host commands and faults go at once. Each household is limited to three streams; a receiver buffering more than 1 MiB is disconnected rather than growing an unbounded queue.

JSON POSTs have a small body limit and an Origin check when an Origin header is present. Static content uses CSP and a no-referrer policy. These checks do not turn plaintext HTTP into an Internet service. See the deployment boundary below.

## Persistent world and two renderings

Session cookies include the persistent session ID in their names. Cookies are scoped to host/path rather than port; the namespace prevents distinct classes on one computer from overwriting one another's credentials.

`world.entities` is the canonical ID-to-entity registry. Every important person, ox, wagon and courier has one identity and one location. Households reference member/principal/property IDs and hold food, relationships, commitments and remembered event IDs. Supporting references must survive absence; they are not instructions to relocate an object.

A stationary location has world coordinates and a valid `siteId`. A traveler has `siteId: null`, endpoints, its own resolved polyline, distance/progress/speed, purpose and causal departure ID. Movement interpolates along that polyline and records departure, first travel progress and arrival. Arrival changes the existing entity; it creates no destination copy. Return travel resolves a fresh path in the other direction.

**What a frame costs** (2026-09-17, [PERFORMANCE_RENDER](docs/PERFORMANCE_RENDER.md)). `drawWorld` draws the ground under the people - relief, the classes of ground, woods, scattered detail, water, fields, roads, a town's ground - into its own canvas (`mapBase`) and lays it down whole on every frame whose key is unchanged (`sameLayerKey` in `public/map-base.js`: the invalidation epoch, the snapshot's world, the map, the canvas size and the camera). `render(snapshot)`, a woods tile or a sheet of art (both coalesced for 200 ms, `redrawForArrival`) invalidates it. The drawing state the ground ended in is carried onto the page's canvas each frame (`readDrawState`/`applyDrawState`). Water is laid down only where a segment can reach the screen (`visibleSegments` in `public/curve.js`), a course is measured for the scatter only against its segments near the view (`segmentsNear`), the page's words are written only when they change (`setText`), and the canvas holds to about a 1080p frame of pixels however dense the screen (`canvasRatio`). The ground's detail hands over across bands of zoom and never moves (`scatterLevels`, `woodsLayers`, `waterWidth`, `creekOpacity`); a class of ground is a table entry in `public/ground-classes.js`. `scripts/perf-render-measure.mjs` measures it with the CPU throttled; `scripts/zoom-lod-shots.mjs` photographs one spot at every wheel step.

**Drawing movement** (display only, `public/motion.js`, 2026-09-16). `ProjectionMotion` draws a traveller linearly from where they were drawn when a tick arrived to the progress the server sent, across the snapshot's `tickMs`. A snapshot of the same tick and minute with a new revision (a command somewhere in the class) keeps the current walk; a next tick whose minute step is in `CALENDAR_STEPS` (the values of `CALENDAR_SCALE`) is a walk, anything else is snapped as a time jump. `GaitClock` plays a traveller's walk, ride or rolling clip by the ground drawn under them in their own drawn height (`STRIDE`, wheels by `clipGait`), capped at the authored rate and floored at `GAIT_FLOOR`; `animated()` in `public/app.js` takes it as `gait`. Nothing here reaches `sim/`: `tests/movement.test.mjs` pins the pace constants and a walk's ground, and `npm run test:movement` measures painted frames. **Amended 2026-09-19, the marker when fast** (owner, by multiple choice): `drawnHeightsPerSecond` is a traveller's drawn speed in their own heights a real second (the server's `step`, or `speed` scaled by the last tick, at the camera's scale, over `tickMs`); past `MARKER_ABOVE` (1.2, the ground the library's walk cycles cover at their authored rate) `wantsMarker` makes them a marker, and back below `MARKER_BELOW` (1.0) a figure, faded over `MARKER_FADE_MS` by `MarkerFade`. Only somebody the server has on the road is measured (`travellerSpeed`): on the tick they arrive they fade to their figure at whatever they went to do (a hunter's one-tick "reading the ground" was a marker throughout until 2026-09-19, `npm run test:hunt`), and a departure fades in rather than jumping, the time since a figure's entry was last touched not counted (`MARKER_STALE_MS`). `ProjectionMotion.journey` and `drawnMiles` are the journey and the distance `position` draws them at, so the marker is never further along than the server has them (`tests/travel-marker.test.mjs`). In `public/app.js`, `travelMarker` decides and `drawTravelMarkers` draws the pin, the portrait, the dotted road ahead and the hit spot in `drawnAt`; a figure fading holds its cycle (`cyclesHeld`); beasts and a wagon going with their family fold into its marker. `window.__travelMarkers` is the proofs' evidence; `npm run test:travel-marker` is the browser proof. **Amended 2026-09-21, away on the road** (owner, after a class on Chromebooks: "if they're moving too fast then players shouldn't be able to follow them until they arrive"): the marker is a rule about how close the camera is, and it cannot help when the ground itself runs out, so the decision of whether a journey may be watched at all moved to the server. `sim/sight.mjs` `tooFastToFollow` asks whether one tick would carry this traveller more than `WATCHABLE_MILES_A_TICK` (3, equal to `ROAD_WINDOW_MILES`) miles of road; if it would, `sim/world.mjs` `seenTravel` projects them with `location: null` and a `travel` of `from`, `to`, `distance`, `mode`, `away`, `miles`, `due` and `back` and nothing else, so the page is never handed a point it may not draw. `halted` and `waitUntil` are carve-outs: somebody who is not moving is never away. The page reads it and decides nothing (`away` in public/map-base.js; `outOfSight` and its constants are gone). The Host is unfiltered as before. `tests/travel-sight.test.mjs`, twenty-one injections, and `npm run test:travel-sight`; the whole rule is docs/MAP_ACCURACY.md §12, `FIC-GONZ-230` and `FIC-GONZ-231`.

**One world unit is one mile.** A person walks `WALK_SPEED` of one mile per twenty-minute tick (3 mph); the family's horse goes at `HORSE_SPEED` (5 mph), the ox and wagon at `WAGON_SPEED` (1.95 mph), and a courier rides at `RIDER_SPEED` (7.8 mph), all `HIST-TEX-093` and `FIC-GONZ-059`; a tick longer than an hour carries a day on the road rather than every hour of it (`roadTicks`). `sim/geography.mjs` builds the region from the checked claims in [HISTORY.md](HISTORY.md): the Guadalupe as terrain, Gonzales on its east bank, the contested ford opposite the town just above the forks of the Guadalupe and San Marcos, Williams's land about seven river miles above the ford on the west bank, two stands of timber, and homesteads scattered along the road and water at varied distances rather than on a grid. Every homestead is on the east bank and no track or bank road crosses a river: only the `crossing` route does, once (`tests/geography.test.mjs`). Every coordinate is invented under `FIC-GONZ-002`; the pattern is anchored.

Sites carry a `kind` — `town`, `homestead`, `ford`, `camp`, `woods` or `junction`. A junction is a shape in the road network and not a place: it has no building and no name on the map. `world.map.terrain` holds `{ id, kind, points }` features for the river, timber, fields and the town commons.

Travel resolves a route through the graph with `findPath()`, a Dijkstra over `world.map.routes`. That is what makes the river a barrier: a household on the east bank reaches the west bank only by way of the ford, because no edge crosses the water elsewhere. Distances therefore differ sharply between households — in a fifteen-household class the nearest home is under two road miles from town and the farthest nearly nineteen.

The student has one map. A single canvas consumes the permitted `snapshot.world.entities` and draws each at its authoritative location under one continuous camera; figure size and label density derive from the camera's scale rather than a local/regional mode. The camera follows the household and widens to include the route while anyone travels; the player may drag or zoom, or choose one of their own people from the roster to watch, and the camera then keeps up with that person as they move until Follow is pressed. A household spread across the county cannot be framed legibly all at once, which is why picking a person to look at exists at all. Moving the camera never moves a person or broadens authorization. The wider public picture is the Host's projected screen, not a second student panel. Cosmetic offsets separate overlapping drawings without changing truth. [docs/ASSETS.md](docs/ASSETS.md) defines feet anchors, coordinates, placeholder proportions, future sprite sizes, animation names and level of detail.

The current template has four named people per household. Thomas has detailed depth; supporting family members and couriers have moderate depth; animals/property use aggregate labels. These are architecture categories, not three completed AI systems. Battle formations hold aggregate position/phase/count data. Canvas draws representative little soldiers from those records, capped at 24 per formation. Decorative soldiers are not independently simulated entities, exact historical troop totals, or additional versions of household characters.

## Truth, reports and fog of war

`world.truth` stores objective topic records. `world.knowledge.households[householdId]` and `world.knowledge.public` separately store received reports. Reports support rumor, unconfirmed, confirmed and contradicted states; received time and observed-event time have separate derived ages. **Only a firmer account is news**: `wouldLearn` refuses the same report twice and refuses a fainter version of something a household already has better, and it is the one predicate used both by a rider deciding whether to stop and by the journal deciding whether to write something down.

**A family is rolled** (`FIC-GONZ-021`, 2026-09-12, [docs/FAMILY_CREATION.md](docs/FAMILY_CREATION.md)). `roll-family` is a lobby action: `familyRoll(seed, householdId)` gives one to twenty (`FAMILY_DIE`; six before 2026-09-14), `compositionFor(roll, die)` reads `FAMILY_FACES` (or the six-sided rule for a household with no `die`), `rollFamily` stores `household.die = 20`, and validation checks the members against the face, `rolledPeople` makes the parents and children with `sex`, `age`, kin and hidden `traits` (`strength`, `health`, `housework`), and `rollFamily` replaces the founding four with ids `hh-N-parent-1` … `hh-N-child-4`, principal first. `rollRefusal` allows it only while the family's record holds nothing but its founding; the server's Start rolls any joined family that still can. Traits never reach a client: the entity projection is a whitelist, `observedBy` is a whitelist, `familyProjection` never reads them, and `tests/family-roll.test.mjs` searches every payload for planted values. `tooYoung` (under ten) refuses work, travel and calls in `choreAvailability`, `modeAvailability`, `callAvailability` and `applyAction`. Absent `sex`/`age`/`traits`/`roll` read as the founding household, so **no save version moved**.

**Stand-in art** (2026-09-12). A student's own people are projected with `sex`, `age` and `band` (`ageBand` in `sim/family.mjs`: infant, small, child, youth, adult); `observedBy` sends only `sex` and `band`. `castVariant` in `public/motion.js` picks the figure from those instead of an id hash, keeping `rust` for the local principal, and `figureScale` shrinks children in `miniPerson`. Both are marked `stand-in:` and listed in `docs/ART_REQUESTS.md`. **Since 2026-09-24 every projection sends a glance from one function** — `seenAs` in `sim/town.mjs` (a student's own family in `projectWorld`, `observedBy`, and the Host's `overviewEntity`): `sex` from `sexOf` (the stated field, else the founding four's role: father and son a man, mother and daughter a woman) or, for a townsperson, the sex authored with their name (`townsfolkSex`, which also answers for a class saved before keepers had one), and `band` from `bandOf` (the age, else a founding parent `adult` and a founding son or daughter `youth`, a `ceiling:`). Never `traits`. **The page has one chooser**, `figureOf` in `public/motion.js` (child's figure if the children's sheets draw them, else `castVariant`): the map (`entityClip`), a seat (`seatFigure`) and the family panel's portrait all ask it (`tests/figures-match-people.test.mjs`). Only something sent with no sex at all — a beast, a rider drawn as the courier — still reaches the id hash.

**Who took part, and where they stood** (2026-09-12). `formationMembers` in `sim/directors.mjs` is everybody whose march was accepted and who stands at `CAMP_SITE`; `standWithTheForce` places each a few yards behind the Texian formation in an id-ordered slot every tick from the gathering on, leaving `siteId` at the camp so witnessing and observation are unchanged. `settleHelp` writes `world.participation.gonzales[personId] = { householdId, role: 'supplied' | 'present', minute }`, which nothing projects. `beginTravel` prepends the person's own position when they stand more than `STANDING_APART_MILES` (0.25) from the place's point. `world.participation` absent reads as none, so **no save version moved**.

**Every report in the slice is carried in person** (2026-09-12). `CONVERSATIONS['gonzales-outcome']` in `sim/encounters.mjs` makes the outcome a rider topic, and its truth is sited at `CAMP_SITE`, so `dispatchReport` starts riders at the camp and `advanceRelays` hands it on. The night crossing is a truth (`CROSSING`, `HIST-GONZ-003`) established at `TIMELINE.crossing` and learned only by `witnessing` households; `offerMarch` requires it and words the call by `receivedMinute - observedMinute`. `sendRider` skips a rider name already in the report's provenance.

**What the hidden stats do, and who answers** (steps 3 and 4, 2026-09-12). `housekeepingSaving` in `sim/family.mjs` reduces what `advanceRoutine` counts as eaten by the best `housework` among people at home; `heavyWorkPace` multiplies a `heavy: true` chore's work ticks by strength. Both are 1 for anybody with no `traits`, so the founding family's numbers do not move. `canAnswerCalls` (a parent, or a stated age of 16+) gates `callAvailability`; `applyAction` no longer requires the principal for `help`, `stay`, `go-see`, `stay-home`, `go-upriver` or `stay-in-town`. `handleChoice` and `handleRumor` record `actorId` on the answer, `offerMarch` and `settleHelp` read it, and `directorProjection` sends `request.answerers` — options per eligible person — with `options` kept as the principal's for older clients.

**What a family knows decides what it is asked** (`FIC-GONZ-020`, 2026-09-12). At the notice the director puts a rider on the road to every household at once, so road distance alone decides when each hears; there is no longer a household-order schedule or a family told on the spot. `offerRequests` reads the household's report: `firmEnough` (confirmed or unconfirmed) opens `world.requests[id]`, the neighbour's call, with `where: 'home' | 'town'`; a rumor opens `world.rumors[id]`, a question projected as `request.kind: 'rumor'` with `go-see` and `stay-home`. Going is an ordinary walk; `witnessing` makes the word confirmed in Gonzales and the call opens there. Firmer word marks an open rumor `overtaken`; a refused rumor suppresses the later call. `world.rumors` absent reads as none, so **no save version moved**. `advanceEncounters` runs two passes so that when two riders reach one family in the same tick, the one sent to that family speaks. `stepWorld` (and `resolveTimeJump`) also calls `advanceEncounters` once before `advanceRelays`, and a rider that finishes a leg keeps it as `report.lastLeg` until that call has looked along it: somebody on the stretch ridden in the tick the rider reached a fork is met, the rider put back halted beside them, before the word changes hands (2026-09-14). `lastLeg` never outlives the tick, so no save version moved.

**A courier is a physical world entity, and there are now two ways one discharges an errand.** A topic with no authored conversation still delivers on arrival at the destination site. A topic with one - `cannon-request`, and only that - is delivered by being **said to a living person who is actually there**, and is carried in legs: a rider goes about `LEG_MILES` and hands the word to somebody going further, who hands it on again. Each hand costs one step of confidence, so the same event reaches a near household as a confirmed report and a far one as a rumor, and `report.provenance` carries the source, the observation minute and everybody who has carried it. The hand-off itself costs no simulated time, so road distance alone still decides *when* a household hears.

`projectWorld()` selects the permitted top-level fields, own household/entities, own events and own reports; the Host receives public events/reports, and in place of `observedBy` the whole class as `others` plus `overview` (`sim/overview.mjs`). Event cause IDs are filtered to events visible to that viewer. Travel projections omit private purpose/cause internals. Raw truth, other household knowledge, seed, future timeline, barriers, complete director state and session credentials are excluded. Director projection separately admits local battle state or public reconstruction frames only when the viewer is eligible. Adding fields to household or report records requires a projection review: those permitted records currently travel with their existing fields, so private future metadata must not be attached casually.

The current observation model is deliberately narrow: students see their own physical household, battle formations when a family member is at Gonzales, anybody standing where one of their own people is standing, and - the one exception to standing-next-to-somebody - **a rider carrying news within `SIGHT_MILES` of one of their own people**, because news that materialises at the moment it is spoken has no approach at all. Other families exist in the shared world but are not otherwise visible to students. **The Host has no fog** (owner, 2026-09-16): `sim/overview.mjs` sends it every person, animal and wagon at its true position and every family's land as it stands, whitelisted field by field; see *The teacher sees the whole class* above. The schematic map's sites/routes are public geography. Broader local visibility needs a server-side visibility model and regression tests; never send hidden entities first and rely on canvas filtering.

## Time, history and Host autonomy

One live `stepWorld()` advances one tick and 20 fictional minutes, progresses travel, applies routines, delivers reports, then advances directors. Timer delays do not trigger a wall-clock catch-up burst. With the launched 1000 ms interval, the 5680-minute slice takes approximately **284 ticks / 4 minutes 44 seconds**, excluding pauses and processing delay. The scenario projection derives `historicalDate` from a fixed September 29, 1835 UTC epoch plus elapsed world minutes; the UI displays that date. The approach falls on October 2. Within-day timings and travel duration are gameplay abstractions. The whole game's roughly 45-minute lesson remains future scope.

The Gonzales factory registers each historical milestone as a compression barrier. Directors establish truth, dispatch news, offer one request per household, close unanswered requests, advance gathering/approach/exchange/withdrawal/resolution, settle personal consequences, release public outcome news and end the slice. Milestone flags, request outcomes, pending couriers, battle state and reconstruction samples are saved, so reconnect/restart does not replay initialization.

The macro-outcome is fixed independently of player choices: Mexican withdrawal and cannon retention by the Texian side. The claim registry and fiction boundaries are in [HISTORY.md](HISTORY.md). Nearby households can see the live battle. The Host remains on public regional information until outcome news becomes public; then it automatically focuses Gonzales and shows labeled delayed reconstruction frames. These are stored phase samples, not a full replay engine. End-of-slice preservation is not the final game's revelation, debrief or epilogue.

`resolveTimeJump(world, minutes)` is an in-process primitive, not a teacher control. It accepts whole-minute jumps up to 60 days in a running world. It stops at the earliest unresolved registered barrier or immediately before significant principal help/service arrival. The caller resumes live stepping to show that moment. Blocked retries are no-ops.

Compression advances elapsed minutes in at-most-20-minute segments using the same travel, food, delivery and minor-recovery routines. It does not add live ticks or execute director milestones inside the jump. Routine visits may complete; significant arrivals wait for a visible step. Existing relationships, loans, service, absences, deaths and major conditions remain. Routine logic creates no death/capture/severe injury, does not settle loans/service, and records a compression event plus household routine summaries. Any new important event system must register barriers; the resolver cannot infer future narrative importance automatically.

## Checkpoints, faults and recovery

The save envelope uses `saveVersion: 3`; the world uses `schemaVersion: 3`. Both went to 2 when real geography replaced the schematic grid, and to 3 when farm work added tools and a field to every household — in each case because a class built on the older model would open into a world missing something it needs. Validation checks entity IDs/locations/references, resources, tools, field state, offers, event references and knowledge consistency. These guards are a foundation, not a complete migration or hostile-file validation system. Unknown save versions fail instead of silently starting a new class.

**A version is bumped when an old save would open a world that is wrong, and not otherwise.** Family keys, presence and trading between households all shipped without moving it, because each has a correct empty answer for a class that predates it: a derived key needs no stored field, presence is never saved, and a class with no offers had none. Bumping would have refused to open every existing class in exchange for nothing. Growth that *does* require a bump is growth where the empty value would be a lie.

Before loading or creating a persistent session, the server acquires an exclusive `<save>.lock` against a canonical local path. The lease is independent of port and released only by its matching PID/token on clean shutdown. Stale or ambiguous locks fail closed. This prevents two servers from forking and overwriting one class history.

A mutation applies the change, validates, increments revision and serialises the session once; that text is both what a refused or failed later change is rolled back to (by parsing it) and what the checkpoint writes. Joins, family-key recovery, Host commands and Play Solo write a temporary checkpoint, flush it and rename it over the main save before broadcasting success; ticks and students' orders are written within `SAVE_WITHIN_MS` (five seconds) or at the third unsaved tick, and `close()` writes whatever is outstanding. On write failure the session goes back to the last completed checkpoint and a transient unsaved fault pauses the live class. Measured costs and the reasoning are in [docs/PERFORMANCE_SERVER.md](docs/PERFORMANCE_SERVER.md). Resume retries a checkpoint before clearing the fault. The last completed file may still say running, so an emergency in-memory pause is not a durable Pause.

A graceful stop is now available from the Host page and from `Stop.vbs`, and `server/main.mjs` removes the launcher's process record on its way out when that record describes itself. `New Class` writes an `archive/` copy of the finished class before replacing it. Full operational instructions and limitations are in [docs/RECOVERY.md](docs/RECOVERY.md). There is still no automatic migration, rotating backup of an ongoing class, damaged-save wizard, identity-transfer wizard, archive-restore UI, settings screen, or always-visible running/stopped indicator while the server is hidden. Closing a browser or choosing End Game does not stop the server. Directory flushing after rename, sudden power loss and cross-machine filesystem leases are not covered guarantees.

## Extension and verification seams

Use `createWorld(seed, count)` or `createGonzalesWorld(seed, count)`, explicit `applyAction()` inputs, `stepWorld()`, `resolveTimeJump()`, snapshots and the event graph for deterministic headless scenarios. `createClassroom({ worldFactory, ... })` supports fixture injection only by trusted in-process code. There is no HTTP phase selection, state mutation, truth inspection or time-skip debug route. `window.__snapshot`, `__received`, `__viewEntities` and `__viewFormations` expose already-delivered presentation evidence, not omniscient state.

`runScenario({ seed, playerCount, strategy, maxTicks })` runs the same Gonzales world without rendering, accepts `mixed`, `help`, `stay` or `idle` bot strategies, and returns world, recorded inputs and metrics. For example, `npm run simulate -- repeatable-seed 15 mixed` prints metrics. The CLI defaults to five households; it does not change the launched game's 15-slot default. Headless bots can begin a running world directly because this is private developer code, not a student-facing solo mode or a bypass in the HTTP Start route.

`extractMetrics(world)` reports per-household survival/health, food, available wagons, separation, lost property, decisions, time since a decision, repeated requests, persistent consequences and memories. These are internal observations, not a score. Evacuation is explicitly `not-modeled`; inherited consequences are `null`. The current decision metric counts recorded choices and is not a completed measure of story quality or parity.

The persistent Event Log carries ID, type, simulated time, actor/household, causal IDs, importance, visibility and optional historical claim/classification. It supplies future deterministic epilogues and current internal metrics. The UI shows only the most recent 12 own events; the saved log remains complete. It is not yet an event-sourced replay system. Checkpoints, whole-state cloning, full snapshots and unbounded event history need profiling before longer arcs; current transport observations are not long-session performance guarantees.

Regression files cover networking, 30-client HTTP/SSE capacity, entity continuity, knowledge/time, persistence failures and the evolving Gonzales slice. Run `npm test`; use [HANDOFF.md](HANDOFF.md) for the current browser commands and evidence. Protect ownership, one-world identity, wire isolation, continuous story, historical anchors and valid refusal before adding content.

## Deployment boundary and unfinished foundation work

[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) separates same-machine browser evidence, independent-device LAN checks and district validation. **Physical-device LAN and actual district validation remain NOT YET TESTED.** HTTP bearer credentials require a trusted network; do not expose this prototype publicly. SSE's per-browser HTTP/1 connection limit also means many tabs in one profile are not a classroom load test.

The launcher bundles a checksum-verified Node executable and keeps an installed-Node fallback; `scripts/bundle-runtime.ps1` produces the runtime, its license and a manifest, and `scripts/launch.ps1` refuses a bundled runtime that does not match its recorded checksum. Graceful lifecycle controls and double-click launch now work on the development machine. The WinForms launcher (`launcher/`) also runs Solo Mode through `launch.ps1 -Solo`/`stop.ps1 -Solo`, and updates itself: `Updater` stages the release's setup program with `--extract`, and `UpdateSwap` renames the running exe aside, moves each replaced entry into `.update-backup` under a journal, and rolls the lot back on failure or on the next launch after an interruption (`scripts/verify-update.ps1`). A signed executable, an approved district package, and an always-visible server status surface remain operational work. Historical geography/travel calibration, researched representative households, broader shared local visibility, pacing/balance, accessible classroom usability and save migrations remain partial. Later Texas Revolution arcs are not implemented. Extend these seams without creating a second world or making the teacher operate historical triggers.
